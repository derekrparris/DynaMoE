DynaMoE

v26.8
High-Performance MoE Inference Engine for Apple Silicon

What's New in 26.8

macOS 26 or later:

26.8 is built against the macOS 26 SDK, so it no longer launches on earlier versions and the update gate says so. The on-device Apple system model and /compact conversation compaction stay gated on Apple Intelligence as well.

DeepSeek V4.1 Flash:

A new model family runs locally, and it is a different class of model from anything else DynaMoE has served. Its forty layers split in two: the encoder half compresses the context into sparse rows and the decoder half reads them back, with latent attention over a compressed cache, six activated experts out of 384 per layer in MXFP4, and DeepSeek's Engram n-gram memory tables, roughly a hundred gigabytes of it, streamed a row at a time. Everything streams from NVMe instead of being held in RAM: the dense backbone is pinned once at load and the expert cache is wired so a read runs at the disk's own rate. It drives the whole turn path like any other family: its own prompt format with a graded Reasoning Effort line (Thinking High / Low / Off), tool calls in the dialect it was actually trained to emit so agent turns execute tools instead of answering prose, images through its built-in vision tower with the cost of a picture priced in the composer before you send it, and prefix reuse across turns so a follow-up re-prefills only what is new (24 of 31 positions reused, 10.7 s then 1.8 s on the published checkpoint). It is served over the local API too. Expect to need roughly half a terabyte of disk and a large-Unified-Memory Mac: the port prices its expert cache from available RAM and wires it for the length of a turn.

Nanbeige 4.3 and Q4/Q8 quantization for dense models:

A 33B dense checkpoint is now identified from its own shape rather than its name (it declares itself a plain Llama), so it keeps its real chat template, its <tool_response> tool turns and its qwen3_coder tool calls. A dense model has no experts to stream, so decode reads the entire weight set once per token: the new Quantize to Q4 / Q8 action (Models → ⋯) rewrites the weights into one contiguous quantized blob beside the snapshot, taking 66 GB to ~34 GB at Q8 and ~22 GB at Q4, with decode around 2.4x faster at Q4 and the published turn still answered token for token. The embedding and output head stay at full precision.

Longer context on every model:

The provisioned row ceiling now comes from the checkpoint's own max_position_embeddings instead of a flat 32,768, so a long-context model can actually use its context (Nanbeige 4.3 reaches 524,288 natively; the ceiling is capped at 262,144 rows). The RAM budget is still the authority that decides what fits, and raising the KV cache to FP8 is what lets a big model reach those lengths on a smaller Mac.

The local API server grew up:

The server that exposes the loaded model over OpenAI- and Anthropic-compatible APIs now speaks both protocols' front doors properly. It serves the models list and retrieve routes in each protocol's own shape, answers Anthropic's POST /v1/messages/count_tokens pre-flight from the turn's own planner (so the count it reports is the usage.input_tokens that turn reports), and serves the legacy POST /v1/completions text route. Image content parts work on both protocols, in every spelling either one allows, with remote URLs refused rather than fetched, and the models list finally says what the model can do: capabilities (vision, thinking, thinking levels, accepted reasoning_effort values), the checkpoint's own context_length, the max_prompt_tokens threshold the server actually refuses on, and a vision_cost range derived from the checkpoint's resize plan so a client can size a timeout before it sends a picture.

Images on cloud models:

Cloud turns can carry screenshots and photos. Deleting a conversation removes its image files, staged and queued images are never silently orphaned, and a provider rejection only downgrades a model when the error names the image part.

Fixes

  • Local server queueing: A request arriving while the app was generating was refused outright with a 503, and under a burst the queue was not serializing at all: twenty-four concurrent requests produced twenty-four turns at once instead of one after another. Requests now wait for whichever turn holds the engine, bounded by the existing queue timeout rather than a new setting, a client that waits past it is told whether it was waiting on other requests or on the app, and concurrent requests run strictly one at a time
  • Request fields that were answered as if they had not been sent: OpenAI's store: false is the one field whose entire meaning is "do not keep this", and it was never decoded, so with content capture on the request's prompt, answer and tool arguments were written to the log anyway; a client's refusal now withholds them and the log row says the client asked for it. The same unknown-key tolerance silently dropped max_completion_tokens (every request using OpenAI's newer spelling ran to the app default of up to 8,192 tokens), frequency_penalty and logit_bias (both now honoured on both OpenAI routes), and Anthropic's metadata. reasoning_effort was validated against this engine's own two words rather than the protocol's four, so minimal and medium (and medium is what OpenAI's SDK sends by default) were answered with a 400 that read as the client's mistake. A request asking for spoken output (modalities, audio) was answered with prose and no message.audio, leaving the client's parser waiting for a field nothing would send; the deprecated functions / function_call spelling was answered with prose and no error at all; web_search_options was dropped, returning ungrounded prose where citations were expected; Anthropic's output_config (JSON output) and mcp_servers were dropped; and one echoed redacted_thinking block refused an entire conversation over bytes this engine could not have read anyway. All of them are now either honoured or refused by name before any generation
  • Model identity: Every route advertised the loaded checkpoint's snapshot directory name as the model id, which for a hub snapshot is a commit hash: unusable as a path segment, unrecognisable in a log row, and different every time the same model was re-resolved. The id is now the repository's short name (DeepSeek-V4.1-Flash-1017), and the old snapshot name is still answered as an alias so a config written against an earlier version keeps resolving. Anthropic clients also get a models list and retrieve route they can actually decode, with a human model name in the field the protocol defines for it
  • Images over the API: The server refused every image content part with a message saying the local model understood text only, which stopped being true once the loaded checkpoint gained a vision tower; the same model read pictures in the chat window and rejected them over the API. Both wire spellings now decode into one form, the picture is placed in the turn that carried each one rather than moved in front of all the text, the expanded prompt is priced before the cache is provisioned, and the session identity includes the picture so a follow-up about a second image cannot reuse the first one's pinned prefix
  • Keychain prompts on every update: Installing a new version produced a "DynaMoE wants to use your confidential information" dialog for each stored credential, and the startup path could ask too. Credentials now live in the data protection keychain, where access is granted by the app's own code-signing identity instead of a per-item prompt, and nothing reads a secret at launch: whether one is stored is answered from item attributes, which macOS returns without a dialog. Credentials written by an earlier version are copied across once from the Stored Credentials card in Settings (Cloud Providers or Agent & Tools), one explained prompt per credential, with the old copy removed only after the new one reads back. A refused read now reports itself as refused instead of claiming no key is stored, and an MCP server blocked by an un-imported credential names the import it needs rather than reporting an unresolved token
  • Repacked models: A repack recorded an empty shape for every tensor, so a repacked Qwen 3.8 priced a routed expert's MLP at its 512-wide default while the weights are 640 wide and answered every prompt with gibberish; the packer now carries real shapes into both manifests, and the sparse-attention indexer's pick no longer depends on tensor order (which differed between a packed manifest and its safetensors source). An interrupted repack also left a zero-length expert layer beside finished ones that the loader preferred anyway, so expert reads ran past the end of the file; a packed model is now only preferred when every layer file is present and full, and repacking is atomic so an interruption cannot leave a half-written blob behind
  • Tool turns on the ChatML families: A turn that followed a tool result built its prompt two different ways (the live continuation opened its reasoning channel spelled one way while the rebuilt history opened another, and the assistant turn marker was emitted twice), so every tool call ended the conversation's reusable prefix and forced a full re-prefill. Both paths now produce the same bytes, a tool result is tagged as one, each family uses its own markup, and the same shape is used over the local API
  • Under the hood: Prefill now chunks for every family rather than only Gemma, so a long prompt's transient memory scales with the chunk instead of the whole prompt; the README and settings guide document DeepSeek V4.1, Nanbeige 4.3, the Q4/Q8 quantizer, and every request field this server accepts, honours or refuses
