### 📦 What's New in 26.11
* **Agent skills, loaded on demand:** A skill is a folder holding a `SKILL.md`. The system prompt advertises only its name and a one-line description, and the model reads the procedure with the `skill_load` tool (plus any `scripts/`, `reference/` or `assets/` files beside it) when the description matches, so an unused skill costs a line of prompt instead of its whole body. Skills are discovered in `~/.agents/skills`, `~/.claude/skills` and `~/Library/Application Support/DynaMoE/skills`, plus any `extraRoots` in `skills.json`; a later folder wins a name collision, and a shadowed skill is reported with the path to remove rather than silently dropped. A skill marked `always: true` renders a "route this kind of work through me" rule into every agent prompt, which is how a judgment skill becomes the default without editing each model profile's system prompt. Settings → Agent & Tools → Skills scans and reloads the folders, installs the `subq-decisions` starter, and lists what it read.
* **SubQ decisions as a native tool:** `subq_decide` asks SubQ's decisions-only `subq-snap-preview` model one to three typed questions about a state and returns probabilities plus confidence — for yes/no gates, routing, triage, classification and ordered scoring, not for open-ended writing. The key lives in the Keychain (or is reused from a SubQ Cloud Provider), never enters a prompt or a log line, and is stripped from every process `shell_run` spawns. A call that uploads images or targets a non-SubQ endpoint asks for approval first, and the card names the origin and files it is about to send to; the approved URL is pinned for that call, so a `defaults write` in the same message cannot retarget the key. Plaintext HTTP is refused except on loopback, and Turbo Mode cannot skip the approval that guards a credential.
* **A Max Output Tokens ceiling that matches the backend:** The slider topped out at one flat 32,768 while the launch path already honoured a checkpoint's own `max_position_embeddings`, so the UI advertised a limit nothing enforced and the first nudge silently rewrote a shipped Nanbeige profile's 65,536 or 262,144. The ceiling is now resolved per backend: a local checkpoint keeps its KV policy (floored at 32,768 so no family loses range, capped at 262,144), and a cloud model gets 20% of its context window — the room auto-compaction already leaves, so a prompt under 80% of the window plus its reply always fits. The line under the slider names which of the policy floor, the checkpoint's own positions, or the policy maximum actually binds, instead of telling an 8k model that its own limit caps it at 32,768.
* **Cloud capacity the provider publishes:** A model's context window and output limit are read from `limit.context` / `limit.output` (and `max_model_len` / `max_output_tokens`) when **Test & Sync Models** runs, so a model that states its capacity no longer starts pinned to the conservative unrecorded-window budget. Hand-typed windows outrank the catalog's and now have a per-model field under Settings → Cloud Providers → Request Behaviour; observed facts are stored separately, so a re-sync cannot overwrite a correction, and re-pointing a base URL drops the old server's numbers while keeping yours. A model with no window of its own is held to 16,384 tokens rather than sent whatever the slider allows — unless its catalog publishes an output cap, which then is the ceiling, because it is the one capacity fact the provider did state. If a provider refuses the reply budget anyway, the step retries once lower and records a cap the refusal names, so the next turn asks for a number the model has already accepted.

### 🐛 Fixes
* **grep_search returning nothing:** On a Mac without ripgrep the fallback never ran — zsh rejected its exclude-dir glob, and even quoted, BSD grep matched that pattern against the search root and skipped everything — so a search reported "0 results" for a tree full of matches. The search is now built without a shell, a non-match exit code or stderr is reported as an error instead of an empty result, a single-file path works, and a process that fails to launch no longer deadlocks the call.
* **grep_search losing real matches:** A soft error such as an unreadable subdirectory makes grep exit 2 after printing matches, and those matches were thrown away. They now come back with a warning, and the tool errors only when nothing matched. A query that is not a valid regular expression (`foo(`) is retried as literal text instead of matching nothing, a cancelled search reports itself as cancelled rather than failed, and the truncation marker no longer counts as a match.
* **A clipped chat composer:** The composer's text view never grew past its first frame and had no scroller, so a pasted prompt was cut off with no way to scroll or to reach the rest of the text with the caret. It now grows with its content up to twelve lines, scrolls beyond that with the caret kept visible, and keeps a gutter so the overlay scroller cannot paint over the last glyphs of a wrapped line.
* **A cloud model wearing a local checkpoint's profile:** A cloud id whose name matched a local family — `qwen3-coder` on Zen, `hf:Qwen/...` on Synthetic — was handed that family's 8,192-token budget and its `presencePenalty 1.50`, and because `cloud://zen/qwen` collapsed to `qwen` before the family gate was consulted, saving a cloud model's sampling settings overwrote the local Qwen profile. Cloud addresses now resolve to one `cloud-model-<provider>-<model>` key whichever form reaches them, and family matching skips them entirely.
* **A truncated turn naming the wrong limit:** Every truncated answer said to raise Max Output Tokens, even when the binding limit was the model's context window or its published output cap, where raising the setting cannot help. The notice now names what actually bound the turn and the one control that can move it, and notes that reasoning shares the same budget.
* **Reset to Defaults that did not reach the session:** Reset restored the profile on disk while the running session kept the old budget and sampling, so the button said "Reset to Defaults" over values it had not changed. It now applies to the live session when that model is the one loaded — without overwriting a system prompt you may have just edited in the Generation tab, which has its own Reset and Save as Default.
* **The Apple Foundation Model's ceiling:** It has no checkpoint, so Settings read the local 32,768 floor while the framework clamps every request to 2,048, and explained the number with a position limit that does not exist. It now reports its own limit in both the discovered-row and fallback paths.
