### 📦 What's New in 26.10
* **No limit on agent steps:** The Max Multi-Step Agent Iterations slider stopped at 100, so a long autonomous task could not say "keep going until it is done" and always ended on a count. A **No limit** switch beside the slider now uncaps the run: the slider keeps the user's last finite number and goes inert, so turning the switch back off restores it rather than leaving a sentinel behind. Both agent loops read the budget through one rule, so the weights path and a cloud run cannot disagree about what "no limit" means, and the cap is resolved per step so a settings change applies to a run already in flight. An uncapped run ends on the model's own `complete`, a tool loop guard (a failed-call streak, a repeated call, the search budget), the model's context limit (the KV budget for local weights, the context window for a cloud provider), or Stop — and the run-end status names only the limit that actually applied, distinguishing a run the model completed, one a tool loop guard stopped, and one that spent its budget. Settings search finds it under "no limit" and "unlimited".
* **Cloud turns ask for the provider's cache:** A cloud agent run re-sends its whole history on every step, and the app neither asked for the provider's prefix cache nor showed what it was billed. Every request now carries a stable session identity (`x-session-id` / `x-session-affinity`, a hash of the conversation rather than its UUID) so a router keeps one conversation on one replica, and providers registered with **Session affinity + cache key** also send OpenAI's `prompt_cache_key`. Both hints are recoverable: a provider that rejects the body field is retried once without it, and the refusal is remembered for the rest of the process only when the retry succeeds and the refusal names the field, so a vague or transient 400 (a concurrency limit, a rate-limit message) cannot switch caching off. The cache key's refusal is remembered per endpoint and model, the affinity headers' per endpoint, so one model on a shared gateway cannot silence its neighbours; a built-in's read-only row offers **Forget Refusals**. The system prompt is no longer rewritten mid-run, so each step extends the cached prefix instead of invalidating it. Cache reads are decoded from every wire shape they arrive in (`prompt_tokens_details.cached_tokens`, `prompt_cache_hit_tokens`, `cache_read_input_tokens`) and merged across a stream's chunks rather than replaced: the Request Log row reads `1,000→50 tok · 800 cached`, its detail sheet splits `800 cached, 100 cache write, 600 billable`, and the Console line carries `cached=800`. **Re-send Images** (Settings → Cloud Providers → Request Behaviour, default on) decides whether every picture rides every request or only the newest user turn's; pictures from earlier turns become a one-line notice instead of a repeated charge.
* **A cloud conversation that knows its ceiling and its bill:** Two registration facts feed the displays, both set from `defaults` because no provider catalog publishes them: context windows per model (`dynamoe_cloud_<provider>_context`, `model=window` entries) and prices per model (`dynamoe_cloud_<provider>_pricing`, JSON in USD per million tokens with `cached_input` and `cache_write_input` rates). With a window recorded the header shows `tokens · N% of window`, where the figure is the context the last request carried — one meaning on every backend, so moving a conversation between a local and a cloud model no longer inflates it — and a send projected past 80% of the window compacts older history with the active provider model before spending the request. The reply budget is capped to the room that threshold leaves, so a Max Output Tokens setting larger than a small window's room is lowered rather than compacting forever against a wall it can never clear; a provider `context_length_exceeded` rejection compacts and retries that step once; a run may compact more than once as it refills its window, and one pass reads at most eight summarizer excerpts, with a longer history summarized as a head-and-tail excerpt that names how much middle history it omitted. `/compact` now uses the active provider model for a cloud conversation and honours `/compact <focus>`, so it works on a Mac without Apple Intelligence. With a price recorded, each turn's status line ends with its cost — `1,204 billed in (1,000 of it cached) / 56 out · $0.0031` — and the header carries the conversation's cumulative spend, summarizer requests included. A step that completed and reported no usage is counted from the app's own estimate and marked `(est.)`, and no cost is invented for it from estimated tokens; a request that was sent and then stopped, failed or was cut off is charged from the same estimate, because the provider billed the prompt it received. A request the provider refused without running the model (an expired key, an unknown model, a rate limit, any 4xx) is not charged, and neither is anything that never left the Mac; a figure below a ten-thousandth of a dollar prints `<$0.0001`. Cloud compaction also shows its progress in the transcript, and its digest rides every step of the run.

### 🐛 Fixes
* **Stop during /compact:** Stop used to commit the partial summary the cancelled summarizer returned and delete every message it never covered. The pass is now checked at each pass boundary and immediately before the rewrite, Stop reports itself instead of a failure or a success, and Stop in a compacting chat no longer cancels an unrelated chat's generation.
* **A turn /compact cut short:** A message larger than one summarizer request was truncated to fit and then deleted along with the summary, so the omitted tail was gone for good. Oversized turns are split across passes instead, which keeps every character while each request stays inside the budget.
* **Two chats compacting at once:** A single compaction flag let a pass in one chat clear the gate another pass still needed, so a send could land in a rewrite and Stop could cancel nothing. Manual compaction state is now keyed by conversation, with a run id so only the owning pass clears it.
* **A finished cloud reply that read as cut off:** A `[DONE]` arriving as the final line of a stream was discarded, so a complete answer was reported as a connection that closed early. The end of a stream is no longer dropped, and finish reasons are classified rather than matched by exact spelling, so only a recognised clean stop lets a summary replace the messages it was written from.
* **Under the hood:** The README and settings guide document the No limit switch, provider prompt caching, Re-send Images, context-window and price registration, and cloud compaction.
