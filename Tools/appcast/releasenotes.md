### 📦 What's New in 26.9
* **Plan Mode:** A new read-only architect mode makes the agent investigate and propose before it touches anything. Enter it from the pill beside Turbo, with ⇧⌘P, or by typing `/plan`; it is a per-conversation mode, so one chat can be planning while another is coding. The write, edit, shell, `git_commit`, `complete` and every MCP tool are withheld rather than discouraged: absent from the prompt and from a cloud model's `tools` array, withheld from the constrained-sampling grammar, and refused by the tool executor if one is somehow emitted. Subagents inherit the restriction, including the Test Runner pipeline, so delegation cannot route around it. What remains is the reading half of the harness — file reads, glob/grep, codebase and symbol search, `git_status`/`git_diff`, web search and fetch, lint diagnostics, and tool discovery — plus a small read core loaded on entry so an investigation does not open with a discovery step. The model ends its answer with a pair of plan markers, which renders as an **Implementation Plan** card with **Start coding**, **Code with Turbo** and **Revise plan**; approving switches the conversation to Code Mode, re-arms the write tools and sends "Implement the plan." as an ordinary user turn. A cloud model that calls tools plans normally; a backend with no tool loop — the Apple on-device model, or a provider registered without tool support — refuses entry with a message rather than flipping a mode its turns could not honour. The mode is fixed for the length of a turn: the pill, `/plan` and the handoff are all refused while a turn is running, because the live turn's prompt, grammar and tool surface were built for the mode it started in, and an approval whose send is refused puts the conversation back in Plan Mode with the transcript unchanged.
* **Cloud providers from Settings:** Adding a remote provider used to mean editing Swift and rebuilding, so the only endpoint the app could reach was the one it shipped with. **Settings → Cloud Providers → Add Provider…** now registers any OpenAI-compatible endpoint at runtime: a display name, an immutable identifier that becomes its Keychain account and the `cloud://` address saved with each conversation, the API base URL, an optional key written only to the Keychain, and an optional documentation link. The base must be `https` (plain `http` is accepted only on loopback), and a URL carrying `user:password@` or a query string is refused rather than saved, because the key belongs in the API Key field and rides the `Authorization` header. Any endpoint that answers `POST <base>/chat/completions` with a Bearer key and lists its catalog over `GET <base>/models` works, and the model list tolerates the envelope differences between gateways. **Test & Sync Models** validates the key and registers the provider's chat models without spending a completion token, and the catalog fetch filters out embeddings, rerankers, speech, moderation and image generators so they cannot become pickable entries that fail on the first send. **Remove** deletes a custom provider's key, registered models, no-tools list and vision marks; a conversation pinned to one of its models then refuses to send with a reselect message instead of silently falling back to local weights. Editing a provider's base URL drops those registrations too, because they describe the server at the old address. Built-in Synthetic stays, cannot be edited or removed, and the registry can never be empty.
* **A summary you can still read:** `/compact` used to fold the conversation into two digests and then show only a marker, so the summary it had just produced survived only inside the prompt. The committed history now opens with an expandable card carrying the same general summary and detailed recap, followed by the marker naming how many messages were compacted. The card is display-only — the digests still travel in the system block — so nothing is sent twice and it costs no context, and it survives a relaunch, unlike the transient progress bubble it replaces. A copy button puts the whole digest on the clipboard.

### 🐛 Fixes
* **Messages that never appeared:** A refused send or a failed model load wrote its reason to state nothing rendered, so the app looked like a dead button at exactly the moment it had something to say, while the feedback that did render — attachment refusals, queued prompts, the history banner — was inserted into the layout around the transcript and shrank it, moving the very text the user was reading. Everything the chat column says now floats in one layer above the composer that cannot resize any pane, with the transcript reserving the layer's height so nothing is held out of reach. Severity is read from the glyph each message already carried, so the tint cannot disagree with the copy; long-running work keeps a progress pill until it finishes instead of vanishing after six seconds; a prompt's ingest counters stay on the transcript row that already showed them instead of re-fading the pill and re-reading it aloud; the history banner sits under the header it used to cover for a whole session; and a failed engine load now records its long reason in the transcript, because a chat that cannot send is permanent rather than six seconds long. The **Advanced Diagnostics** settings tab went with it: its three buttons all depended on a buffer no reachable routine ever filled, so every press could only report failure.
* **Images offered to models that cannot see them:** The attach menu stayed enabled for a text-only model, so picking an image produced a generic refusal that never named the selected model, and sending an already-staged image offered the same "switch models to attach one" advice instead of the fix that applied. Both menu items are now disabled with a tooltip that explains why, the refusal names the selected model and the fix for the situation — switch models before attaching, or remove the attachment before sending — and switching models retracts a stale refusal or raises a fresh one for images already staged.
* **Under the hood:** The README and settings guide document Plan Mode, runtime provider setup and the compaction summary card.
